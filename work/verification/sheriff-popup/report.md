# Mobile sheriff selection and decision popup

13 October 2026. Mobile sheriffs no longer need to scroll down to the decision panel. A native dialog opens on negotiation: its first step contains only names and chosen character avatars for eligible merchants. Selecting a merchant sends the existing command and waits for the public selected ID before exposing that merchant's offer and decision actions. The detail step retains the declaration, PASS/INSPECT buttons and existing confirmation/version guard. Back or dismissal clears unsent confirmation; a fixed safe-area opener allows reopening. Desktop retains an inline panel with avatar/name choices.

Resolution and round completion continue in the mobile popup. It displays the same public result fragment as the existing result panel, then the original next-merchant/summary/end-round command. PASS still reveals no card identities. Pending/error/reconnect/readonly feedback and original retry/control-takeover controls remain available inside the modal.

`SheriffDecisionPanel` owns presentation/media/dialog state only; `SheriffControls` retains command and confirmation ownership. Media subscription uses an SSR snapshot and cleanup; dialogs close on unmount/resize. Native background inertness plus scoped Tab edge cycling, Escape, focus restoration and scroll lock support keyboard use. Touch landscape is supported. Preview observes modal opening to reveal its iframe when the parent page was previously scrolled; it does not scroll on ordinary offer/revision updates. Both observers are cleaned up.
