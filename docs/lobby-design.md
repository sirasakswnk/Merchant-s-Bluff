# ล็อบบี้โต๊ะกลม

12 ตุลาคม 2026 ผู้ใช้เลือกให้เริ่มเฉพาะล็อบบี้ก่อนเกม โต๊ะไม้กลมและตัวละครล้อมรอบ ใช้สีและฟอนต์ต่อเนื่องกับ home.html ไม่ใช้ merchant-gate.html เป็นแบบสุดท้าย

- ผู้เล่นเห็นตัวเองอยู่ล่างเสมอ ไอคอนใช้ avatarId และ SVG ตัวเดียวกับที่เลือกบนหน้าแรก ชื่อจริงไม่ตัดทิ้ง มีสถานะพร้อม/เชื่อมต่อและมงกุฎผู้จัดห้อง
- วางผู้เล่นที่เหลือตามลำดับสัมพัทธ์ของที่นั่งเดิม ปรับเฉพาะภาพของผู้ชมแต่ละคน ไม่เขียนหรือสลับ seatOrder จริง เมื่อมีน้อยกว่า4คน แสดงที่ว่างจนถึงขั้นต่ำจาก rules snapshot
- รหัสห้อง/คัดลอกลิงก์อยู่เหนือโต๊ะ ปุ่มพร้อมอยู่ใต้ที่นั่งตัวเอง เริ่มเกมกลางโต๊ะเฉพาะผู้จัดห้อง ใช้คำสั่งเดิมและเปิดเมื่อมีคนครบขั้นต่ำ ทุกคนพร้อม และแท็บส่งคำสั่งได้
- ลิงก์เต็มเปิดดูได้ หากคัดลอกไม่ได้จะเปิดช่องให้เลือกคัดลอกเอง รองรับ pending/retry, offline, read-only/control takeover และรับตำแหน่งผู้จัดห้องเดิม
- ขนาด360/390/430pxและเดสก์ท็อปใช้โต๊ะวงกลมจริง เมื่อพื้นที่เล็กมากหรือขยายข้อความ200% ปรับการวางโปรไฟล์ให้อ่านครบโดยยังให้ตัวเองอยู่ท้าย/ล่าง สีสถานะมีข้อความและสัญลักษณ์ประกอบ ไม่ใช้สีอย่างเดียว ปิด transition เมื่อ reduced motion

เปิด [พรีวิว6คนบนมือถือ](http://localhost:4100/preview?scene=lobby&role=sheriff&players=6&width=390) ตัวเลือกนายด่านในพรีวิวล็อบบี้หมายถึงมุมมองผู้จัดห้องเท่านั้น ก่อนเริ่มเกมยังไม่มีนายด่าน

`RoomView` ส่งเฉพาะ lifecycle LOBBY ไป LobbyView ส่วน RoomClient ยังคง Auth/realtime/storage/commands เดิม LobbyView ไม่มี data SDK ส่วนกติกาอ่าน snapshot ไม่แก้ engine/backend/Rules/ราคา/สำรับ/rulesVersion มี CSS Modules แยกเพื่อไม่กระทบหน้าแรก/เล่นเกม/ผล/คะแนน

ผู้ใช้ตกลงว่าเมื่อคนอื่นเป็นนายด่านจะอยู่บน สลับภาพนายด่านเก่า/ใหม่ โดยตรึงตัวเองล่าง หากตัวเองเป็นนายด่านให้คงล่างพร้อมป้าย 13ตุลาคมลงมือหน้าเกมตามข้อตกลงนี้แล้ว ดู [หน้าเล่นเกม](game-table-design.md)
