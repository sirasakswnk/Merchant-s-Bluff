# พรีวิวดีไซน์โดยไม่ต้องเล่นจริง

เปิด `/preview` เช่น **http://localhost:4100/preview** ตัวอย่างใช้หน้าจอเดียวกับเกมจริง โดยรับข้อมูลตัวอย่างแทนการเชื่อม Firebase ไม่ต้องสร้างห้อง มีป้าย “ตัวอย่างดีไซน์ · ไม่มีห้องจริง” อยู่เหนือภาพ

เลือกจากแถบด้านบน:

- หน้าจอ: ล็อบบี้ เตรียมสินค้า จัดกระเป๋า เจรจา ผลให้ผ่านสองแบบ ผลตรวจสองแบบ สรุปรอบ คะแนนสุดท้าย และยุติเกม รวม11ตัวอย่าง
- มุมมอง: พ่อค้า/สมาชิก หรือ นายด่าน/ผู้จัดห้อง
- ผู้เล่น: 4/5/6คน
- สถานะ: ปกติ ออฟไลน์ แท็บอ่านอย่างเดียว รอยืนยันผล กำลังส่ง ผิดพลาด หรือกำลังโหลด
- ขนาด: พอดีกับหน้าต่าง หรือ360/390/430/1280/1440px เป็นขนาดจริงของiframeและใช้responsiveแบบเดียวกับเกม ภาพขยายสูงตามเนื้อหาเพื่อดูทั้งหน้าได้

ปุ่มในตัวอย่างให้ลองเลือกไพ่ เสนอเงิน เปิดconfirmation ตรวจ/ให้ผ่านและเห็นผลได้เฉพาะในตัวอย่าง “รีเซ็ตตัวอย่าง” คืนข้อมูลเริ่มต้น “เล่นเอฟเฟกต์ซ้ำ” ดูกระเป๋าแดงอีกครั้ง มีปุ่มเปิดเต็มหน้าสำหรับดูโดยไม่มีแถบตั้งค่า

ฉากคะแนนสุดท้ายตั้งเงินตัวอย่างให้คนที่เหรียญมากสุด (80) ไม่ได้ที่1 เพื่อเห็นว่าอันดับมาจากคะแนนรวม และ4คนมีกรณีคะแนนเสมอที่ตัดสินด้วยสินค้าถูกกฎหมาย ฉากเล่นเกมรอบ2ขึ้นไปมีประวัติรอบก่อนหน้า (สูงสุด2รอบ) สำหรับสมุดบันทึกด่านบนdesktop คำนวณผลด้วยresolveBagเดิมโดยใช้ledgerตัวอย่างแยก เงินตัวอย่างของฉากจึงไม่เปลี่ยน ฉากเล่นเกมมี “เปลี่ยนนายด่านตัวอย่าง” เพื่อดูการสลับภาพตำแหน่งโดยยังคงviewerเดิมรวมเมื่อเราเป็นนายด่าน มีเฉพาะในpreview การเปลี่ยนตัวอย่าง/รีเซ็ตไม่ส่งคำสั่งเกมจริงหรือเขียนstorage ดูdocs/game-table-design.md

ค่าที่เลือกอยู่ในURLและrefreshกลับมาได้ ตัวอย่างเช่น:

```text
/preview?scene=pack&role=merchant&players=4&width=390
/preview?scene=pass-contraband&role=sheriff&players=6&width=430
/preview?scene=game-over&role=sheriff&players=6
/preview?frame=1&scene=inspect-legal&role=merchant&players=5
```

## ขอบเขตข้อมูล

ข้อมูลทั้งหมดเป็นตัวอย่าง ไม่เรียกRooms API/Auth/RTDB ไม่จองรหัสห้อง ไม่สร้างบัญชี ไม่บันทึกdraftหรือแก้active-room/pending requestของผู้เล่น ไม่คัดลอกข้อมูลจากห้องจริง ไม่เขียนคลิปบอร์ดจากปุ่มคัดลอกในภาพ

สินค้า/ราคา/ค่าปรับ/ค่าชดเชยและจำนวนสำรับอ่านconfig0.2/360ชุดเดียวกับแอป ผลตรวจและคะแนนตัวอย่างคำนวณด้วยpure functionsเดิม ไม่ใช่ผลplaytestหรือเกมจริง ไม่เพิ่มseed/debug endpointบนbackend ใช้room IDตัวอย่างที่ผ่านvalidationของห้องจริงไม่ได้ และmetadataของrouteตั้งnoindex

`RoomView` เป็นpresentationร่วม ส่วน`RoomClient`รับผิดชอบAuth/realtime/commandsจริง `RoomPreview`ส่งข้อมูลและcallbackเฉพาะในmemory เกมจริงยังเก็บdraftตามเดิมแต่previewส่ง`persistDraft=false` การแก้หน้าตา`RoomView`/game-controlsจึงปรากฏทั้งสองที่

ผลตรวจอยู่ [รายงาน preview](../work/verification/preview-route/report.md) ขั้นนี้พร้อมในเครื่อง ยังไม่ได้commit/push/deployProduction งานหน้าแรกที่ทำก่อนหน้าคงไว้
